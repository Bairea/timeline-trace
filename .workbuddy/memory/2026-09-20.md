## 已定关键决策

- 记录交互：B2 自由画 + 精确输入为主，拖动为微调（用户明确选 B2 而非 B1 吸附）。
- 命中判定：**时间重叠度自动算**，不做手工勾选（用户确认「自动判定够用」）。
- 硬需求：导出每天每段的精确时间分配（CSV UTF-8 BOM / XLSX 多 sheet）。
- 栈：Python FastAPI + 原生 JS 单页 + 单 SQLite；主要在电脑上用；白天随手记。
- 存储：时间一律存分钟数整数；跨零点块单根、归属起始日。
- 删除：可视化块上可删，真删除 + 5 秒撤销，落库保留 `deleted_at` 软删除标记。
- status 固定四档：aligned / offset / unrecorded / unplanned（`short` 已归并入 offset）。
- 部署：云服务器公网 IP **无域名**，用户选定 **方案 A 自签证书**（已知风险：无法防 MITM，文档已记录）。必做：访问口令 + 每日备份 + 不暴露 8000 端口。
- 明确不做：多用户、移动 App、自动追踪、任务管理、推送提醒。

## P0 + P1 已实施完成（同日）

- 分支 `feature/mvp`，P0（骨架/依赖/venv/pytest 基线）+ P1（纯逻辑层）全部走 TDD。
- 文件：`app/compare.py`、`app/parser.py`、`tests/test_compare.py`（16 项）、`tests/test_parser.py`（11 项）。**28 项测试全绿。**
- **测试捕获两个真实缺陷（重要，勿回退）：**
  1. **`compare_day` 会静默丢弃实际块**：两个实际块争一个模板槽位时，落败者从输出中消失（3 个实际块只出 2 行）。这是记录类工具最致命的失效模式。已改为保证不变式「每个实际块必须至少出现在输出中一行」，落败者归 `offset`，并加 `test_every_actual_block_appears_in_output` 等专项测试锁定。
  2. 我自己最初写的测试对 `unplanned` 预期有误：落在模板窗口内的其他活动按设计 §5.1 应为 `offset`（重叠>0），非 `unplanned`。已修正测试（实现是对的）。
- 环境：项目内 venv 位于 `.venv`，用 `.venv/Scripts/python.exe -m pytest` 运行。
- 已知微小边界（未修，YAGNI）：输入 `24:00 干活` 会产生 `start=1440`（等同次日 00:00 的退化表示），不崩溃但语义易混，正常不会这么输。
