### 阈值问题已解决（同日晚）

用户同意后实施，阈值定为 **5 分钟**，并**额外发现纯绝对阈值会误伤短模板块**：
- 模板「出门前准备」仅 5 分钟（07:30-07:35），纯绝对阈值 5 会让它挪 1 分钟即重叠归零 → 被判 `unrecorded`（用户明明做了，系统说没做）。

### 验证方法的重要经验（省时间）

**`agent-browser` 在本机存在跨命令上下文漂移**：每次 `open`/`eval` 可能落在不同 JS 上下文，导致读到 `about:blank`、`blockCount:0`、`state.rows` 为 `undefined` 等假象。曾据此误判「左栏空白」「删除/微调失效」，实际全是工具噪声。

- **更可靠做法**：交互行为直接对真实 HTTP 端点做断言序列（Python `urllib`），这是应用行为的权威验证。

## 16:40 修复「24 小时轴挤成一坨」+ 视觉重做收尾

**缺陷报告**：用户反馈「你现在改的上下完全压在了一起」。根因是**单位语义混淆**——
`applyZoom()` 里写 `const axisH = state.zoom * 24`，把 `state.zoom` 当「每小时像素数」用；
但 `ZOOM_DEFAULT = 1` 是**倍率**语义，于是轴高算成 `1 × 24 = 24px`，24 小时全挤成一坨。

**修复方式（单一真相源）**：
- 引入 `BASE_HOUR_PX = 72`，`hourPx() = BASE_HOUR_PX * state.zoom`
- `axisH = hourPx() * 24`，默认 = **1728px**
- `state.zoom` 全局统一为**倍率**语义，像素换算只在 `hourPx()` 一处发生
- 连带修掉 3 处残留旧语义：`renderRuler` 的 `stepH` 阈值（改用 `hourPx() < 48 / < 96`）、
  `renderHourLines` 的半小时线条件（`hourPx() >= 96`）、`bindWheelZoom` 的锚点计算
  （`state.zoom * 24` → `hourPx() * 24`，并改用 `.axis-wrap` 实际高度更稳）
- 移除 `applyZoom()` 里多余的 `renderHourLines()` 调用（`renderTemplate`/`renderActual`
  内部已各自清轴重建，重复清空让「谁负责清轴」含糊）

**验证结果**：
- `.shots/geom.test.js` 纯逻辑断言 **11/11 通过**（含 1x/2x/0.5x 轴高、跨零点块高、
  相对位置不随缩放改变、5 分钟块 6px→12px 下限）
- 各倍率轴高实测：0.5x=864 / 0.75x=1296 / 1x=1728 / 1.25x=2160 / 1.5x=2592 / 2x=3456 / 3x=5184px —— 无塌陷档位
- HTTP 核验服务端已提供修复后资源（`BASE_HOUR_PX = 72`、`--axis-h: 1728px` 兜底、4 个缩放控件）
- 后端回归 `126 passed`

**教训**：定义 CSS 变量型几何量时，必须把「语义单位」写进注释并只留**一个**换算入口。
本轮把这条写进了 `app.js` 常量区的注释里。

## 20:32 「预期时间线是否该独立成配置文件」的现状审计（只读，未改动代码）

用户问：做成稍正式的项目，是否把预期时间线（模板）做成单独配置文件更好。
结论：**方向对，但缺失的不只是「配置文件」，而是「配置文件 → 模板」这条通路。**

### 已实测确认的缺口（改代码前必须一起补，否则配置化只是换位置）

1. **模板完全不可编辑——前端没有任何入口。**
   `static/` 只有 index / stats / login 三个页面，无模板编辑页。
   `attachBlockEvents` 只对 `#actAxis .block` 生效（app.js:91、:547），
   模板栏 `#tplAxis` 从头到尾**没有任何事件绑定**（全文仅 2 处引用：:209 渲染、:466 画 now-line）。
   → 设计文档 §6.3「模板块不能直接删，只能改，须进模板编辑页」中的「模板编辑页」不存在。
2. **模板本身恒为只读。** `.block` 基础样式带 `cursor: grab`（style.css:332），
   所以模板栏**看上去**可拖，实际不响应任何指针事件——假交互暗示。
3. **后端模板写接口存在但零测试。** `POST /api/templates/{id}/blocks`、
   `PUT/DELETE /template-blocks/{id}` 均已实现（app/api/templates.py:37-80），
   但 `tests/` 里没有任何用例覆盖（`grep template-blocks tests/*.py` 为空）。
   → 即"能改却没人改过"，静默腐化风险最高的一类接口。
4. **模板只能靠 seed 播种。** `app/seed.py` 是唯一写模板的代码路径，
   幂等键是 `name == "工作日"`。**改了 WORKDAY_BLOCKS 常量不会更新已有库**——
   函数一进 `if existing: return existing["id"]` 就返回。
   → 这是"改常量却看不到变化"的典型陷阱，配置化前必须处理。
5. **阈值常量散落三处**（与本问题同源，都属"代码即配置"）：
   `app/compare.py` TOLERANCE_MIN=15 / MIN_OVERLAP_MIN=5 / MIN_OVERLAP_RATIO=0.5；
   `app/parser.py` MAX_SPAN_MIN=16h / DEFAULT_DURATION_MIN=30；
   `app/stats.py` SLEEP_MIN_HOURS=7.0 / PROJECT_MIN=(45,90) / EXERCISE_MIN=(5,20)。
