### 缺陷确切形态（已取证，非凭记忆）

原正则 `^(start)\s*(sep)?\s*(end)?\s*(name.*)$` 中 `sep` 与 `end` **都是可选组**，
正则引擎在 `08:30 20:30-21:30` 上让 `sep` 取 None、`end` 吞掉 `20:30`：

```
groups={'start': '08:30', 'sep': None, 'end': '20:30', 'name': '-21:30'}
-> 510->1230，跨度 720 分钟
```

带名字时更糟：`'08:30 20:30-21:30 干活'` → 名字变成 `'-21:30 干活'`，
**用户写的内容直接丢了一半**。

### 修法：分层，而不是调正则

**分组正则无法表达「终点的存在依赖于分隔符」这种依赖关系。**
改为：`_HEAD` 只拆出起点，剩余部分由 `_split()` 顺序判断——
① 起点后紧跟 `-/~/至` → 显式区间（无时刻则是开放区间）；
② 起点后是空格 + 另一个时刻，且**该时刻后面不跟分隔符** → 视为省略分隔符的区间；
③ 否则第二个时刻属于名字。

纯空格区间 `08:30 09:30` 的能力**保留**，未修坏。

### 过程中的两次自我纠正

1. **第一版修复是无效的**：我只加了 `_space_separated_range()` 兜底，
   但没动 `_PATTERN`——`end` 组仍在原正则里被吞掉，新分支根本没机会执行。
   3 条测试依然 RED。**修 bug 时先确认改的代码真的在生效路径上。**
2. **测试期望值我写错了**：用 `now_min=600` 配 `08:30`，断言 510，
   实际 1950。这不是 bug——`start < anchor and start < now_min` 时加一天
   是**既有语义**（晚上 20:00 记 08:30 指明天早上）。改测试的 `now_min=0`。
   **遇到「期望 vs 实际不符」，先判断是缺陷还是既有设计，别急着改实现。**
